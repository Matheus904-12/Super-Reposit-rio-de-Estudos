## Exercícios sugeridos
1. Peça ao Copilot para explicar uma classe existente sem modificá-la; valide a explicação contra o código.
2. Peça testes unitários para uma regra com casos de sucesso, erro e limite; revise cada cenário.
3. Peça ajuda para investigar um bug; exija hipóteses e evidências antes de aceitar uma correção.
4. Solicite uma refatoração pequena preservando comportamento; confira diff e testes.
5. Peça documentação de uma API; confirme rotas, parâmetros, respostas e erros no código.
6. Gere um SQL com JOIN e agregação; valide com dados pequenos conhecidos.
7. Peça para apontar riscos de segurança; trate a resposta como checklist, não como auditoria definitiva.

## Regras
- Não inserir chaves, tokens, senhas, dados pessoais ou dados de clientes nos prompts.
- Não aceitar dependências novas sem entender a finalidade.
- Não aceitar testes que só confirmam a implementação atual sem testar o comportamento esperado.
- Não considerar código correto apenas porque compila.
- Para exercícios de segurança, use apenas ambientes próprios/autorizados.
