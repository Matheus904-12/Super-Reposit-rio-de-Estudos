# Super Repositório de Estudos — Matheus Lucindo

> Um índice central para preservar minha trajetória de aprendizagem, organizar projetos acadêmicos e documentar estudos de desenvolvimento de software.

## Objetivo

Este repositório organiza o acervo sem apagar nem substituir os repositórios originais. A ideia é manter links para a origem, registrar o contexto de cada trabalho e destacar separadamente os projetos que representam melhor meu nível atual.

## Regras do acervo

1. **Preservar os originais:** não apagar, renomear ou mover os repositórios de origem como parte desta organização.
2. **Não copiar às cegas:** antes de importar código para cá, conferir segredos, dados pessoais, licenças e autorização para publicar.
3. **Manter a origem:** cada projeto deve registrar o link do repositório original, período aproximado, contexto e tecnologias confirmadas.
4. **Não inflar o portfólio:** exercícios pequenos podem ficar no acervo, mas não precisam ser apresentados como projetos profissionais.
5. **Separar aprendizado de produção:** códigos de exercícios de Copilot e Microsoft Learn devem ser identificados como estudos.
6. **Não incluir credenciais:** tokens, senhas, chaves, arquivos `.env` e dados reais nunca devem ser adicionados.

## Como preencher

- Comece pelo `catalogo/repositorios.csv`.
- Classifique cada repositório por período e finalidade, usando a data real de criação/commits quando disponível — não apenas o nome.
- Para trabalhos de 2023–2024, registre o contexto do curso técnico.
- Para cada projeto importado, adicione um `README.md` com objetivo, tecnologias verificadas, como executar e link de origem.
- Mantenha projetos de empresa ou com código de terceiros fora deste acervo público até confirmar autorização.

## Portfólio profissional

Este repositório é o **arquivo de aprendizagem**. Os projetos mais fortes devem continuar tendo seus próprios repositórios, READMEs específicos e demonstrações independentes.
